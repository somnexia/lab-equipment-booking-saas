Открыть в [diagrams.net](https://app.diagrams.net) → экспорт PNG/PDF для отчёта.

---

## Назначение

Показать **пошаговый алгоритм** и **ветвления** при создании брони: что делает пользователь, что выполняет API и когда обращается к MySQL.

В отличие от диаграммы последовательности (временной порядок сообщений), диаграмма действий акцентирует **логику решений** и **параллельные зоны ответственности** (дорожки).

---

## Дорожки (swimlanes)

| Дорожка | Содержание |
|---------|------------|
| **Пользователь** | Вход, каталог, выбор слота, подтверждение, результат |
| **Система (Express API)** | JWT, авторизация ролей, REST, бизнес-проверки |
| **База данных (MySQL)** | SELECT users/equipment, INSERT bookings |

---

## Основные действия

| Шаг | Дорожка | Действие |
|-----|---------|----------|
| 1 | Пользователь | Открыть приложение |
| 2 | Пользователь / Система | Вход (если не авторизован) |
| 3 | Система / БД | `POST /api/auth/login` → `SELECT users` |
| 4 | Пользователь | Просмотреть каталог |
| 5 | Система / БД | `GET /api/equipment` |
| 6 | Пользователь | Выбрать оборудование и время |
| 7 | Пользователь | Подтвердить бронь |
| 8 | Система | Проверить роль (student, researcher, …) |
| 9 | Система | `POST /api/bookings` |
| 10 | Система / БД | INSERT, `status = active` |
| 11 | Пользователь | Получить подтверждение |

---

## Условия (ромбы)

| Условие | Да | Нет |
|---------|----|-----|
| Авторизован? | → каталог | → форма входа |
| Роль разрешена для POST? | → создание брони | → 403, сообщение об ошибке |
| `equipment.status = available`? | → проверка слотов | → ошибка |
| Нет пересечения с `active` бронями? * | → 201 Created | → ошибка |

\* Сейчас в коде **не реализовано**; планируется в `sp_create_booking` (см. note на диаграмме).

---

## Конечные состояния

| Исход | Состояние брони / UI |
|-------|----------------------|
| Успех | `bookings.status = active`, пользователь видит подтверждение |
| Ошибка | Сообщение (401/403/500 или бизнес-ошибка), конечный узел «отказ» |

После успеха возможны переходы из [06-state-diagram.md](06-state-diagram.md): `active` → `completed` / `cancelled`.
