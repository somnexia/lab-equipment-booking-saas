## 1. Состояния бронирования

Поле БД: `bookings.status` (ENUM).

| Состояние | Код | Описание |
|-----------|-----|----------|
| Начальное | — | Точка входа при создании записи |
| Активная | `active` | Слот забронирован, время ещё не истекло |
| Завершена | `completed` | Опыт/работа выполнены или `end_time` прошло |
| Отменена | `cancelled` | Отмена пользователем или администратором |

### Переходы

| Из | В | Событие / условие |
|----|---|-------------------|
| [*] | `active` | Создание брони (UC-30), оборудование доступно |
| `active` | `completed` | Наступило `end_time` или ручное завершение |
| `active` | `cancelled` | Отмена (UC-33): студент/исследователь/админ |
| `completed` | [*] | Конечное состояние |
| `cancelled` | [*] | Конечное состояние |

**Ограничения:**

- Из `completed` и `cancelled` обратно в `active` не переходят (новая бронь = новая запись).
- Студент не выполняет физический DELETE — только `status = cancelled` (см. CRUD-матрицу).

## 2. Состояния оборудования

Поле БД: `equipment.status` (ENUM).

| Состояние | Код | Описание |
|-----------|-----|----------|
| Доступно | `available` | Можно создавать брони `active` |
| Техобслуживание | `maintenance` | Плановое ТО, бронь недоступна |
| Неисправно | `broken` | Поломка, бронь недоступна |

### Переходы

| Из | В | Событие / актор |
|----|---|-----------------|
| [*] | `available` | Добавление оборудования в каталог |
| `available` | `maintenance` | Техник/менеджер: плановое ТО (UC-23) |
| `available` | `broken` | Обнаружена неисправность |
| `maintenance` | `available` | ТО успешно завершено |
| `maintenance` | `broken` | ТО не устранило проблему |
| `broken` | `maintenance` | Начат ремонт |
| `broken` | `available` | Ремонт завершён, прибор исправен |

---

## Связь двух автоматов

| Ситуация | Поведение системы (целевое) |
|----------|----------------------------|
| `equipment` → `maintenance` или `broken` | Новые брони со статусом `active` **запрещены** |
| Уже существующие `active` брони | Отменить (`cancelled`) или дождаться `completed` — политика лаборатории |
| `equipment` → `available` | Снова разрешено создание броней |

Планируется проверка в хранимой процедуре `sp_create_booking`.

---

## Соответствие коду

| Переход | Реализовано сейчас |
|---------|-------------------|
| Создание `active` | Да (`BookingsService.create`) |
| `active` → `completed` / `cancelled` | Частично (ручной `UPDATE` через API) |
| Смена `equipment.status` | Частично (`PUT /api/equipment`, роль technician) |
| Автозавершение по времени | Нет (фоновая задача / cron — в планах) |
| Запрет брони при non-available | Нет (планируется в SQL) |
